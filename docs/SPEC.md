# EXIF Date Sync — 現行仕様

## 目的・基本設計

EXIF `DateTimeOriginal`を読み、ユーザーが選んだ画像ファイルの**変更日時（mtime）だけ**を撮影日時へ合わせる個人用アプリ。macOS／Android対応、Flutter共通のMaterial 3画面。Exif解析エンジンを作るアプリではない。**開発順序はmacOS完成→Android完成→将来的にWindows移植**。Windowsは現時点で未対応であり、先行する共通抽象化やWindows固有処理は追加しない。

| 領域 | macOS | Android |
| --- | --- | --- |
| EXIF読取 | 外部インストール済みExifTool（同梱なし） | AndroidX ExifInterface 1.4.1 |
| mtime更新 | ExifTool `FileModifyDate`、小数秒が必要な場合はFoundation | `File.setLastModified` |
| Undo | 端末内JSONで最新1バッチ | 端末内SQLiteで最新1バッチ |
| 読み書き範囲 | 明示選択した単一フォルダと、指定時は配下 | 内部ストレージの`DCIM`／`Pictures`／`Download`配下の選択フォルダ |
| 画像 | JPEG／PNG／HEIC／HEIF／HIF／Sony ARW／Leica RWL／Panasonic RW2／Olympus ORF／DNGほかExifTool対応候補 | JPEG／PNG／HEIC／HEIF／ARW／RW2／ORF／DNG（RWLは対象外） |

拡張子による対象候補と**個別のRAWが実際に読めることは別**。Android DNGの実コピー1件では標準EXIF日時を取得できず、ライブラリの制約例として保持する。別日時タグに代用しない。

## 撮影日時と対象判定

- **EXIF `DateTimeOriginal`のみ**採用。オフセットが明記されていれば適用し、なければ常にUTC+09:00（JST）。小数秒は可能な限り反映する。
- 欠損・不正・1970年より前、明らかな未来の日時は対象外。mtime／birthtime／ファイル名／XMP／`CreateDate`／`DateTimeDigitized`／`ModifyDate`は代替根拠にしない。
- 現在mtimeと撮影日時が等しい場合は「変更不要」、欠損は「日時なし」、取得失敗は「読み取りエラー」。mtime更新前にファイルとEXIFを再確認する。
- 画像バイト、EXIF/XMP、ファイル名は書き換えない。**macOSのファイル作成日時（birthtime）は不変とは保証しない。** 2026-11-10の専用コピーではmtime更新に伴ってbirthtimeも変化し、元mtimeを復元してもbirthtimeは戻らなかった。birthtime維持・復元用の追加処理は実装せず、副作用として明示する。

- Androidの一括更新には現行実装上、**1バッチ20,000ファイルまで**の技術的上限がある（`AndroidBatchWriter.kt`）。課金・無料版の制限ではない。大量件数の運用評価後に扱いを見直す。上限を超えても処理できると案内しない。

## UIと操作

- 単一フォルダを選択。サブフォルダ込みは切替可能（初期OFF）。走査中に逐次行表示し、中止可。中止・エラーで一覧不完全の場合は**更新禁止**。再スキャン時は旧選択を初期化。
- 行にファイル名（相対パス）、撮影日時、現在mtime、状態、選択チェックを表示。「要更新」のみ初期チェックON。処理前に件数を確認し、明示承認を受ける。
- macOS：上下余白を抑えた4列表を維持し、状態の要更新を初期表示で先頭に置く。4列を常時表示し、各列を昇順／降順に並べ替えられる。「要更新のみ」の絞り込み、**要更新全選択／全解除**、既定アプリで写真を開く操作。RAWを走査対象に含めるか切り替えられる（初期ON）。右側の固定プレビュー欄に、ファイル名のクリックまたは一覧での上下矢印で選んだ画像を表示する。プレビュー欄から関連付けアプリで開ける。初期ウィンドウの内容領域は1120×720ポイント。更新と利用可能なUndoは一覧の下に表示する。更新確認は選択件数と、必要な場合だけ前回Undo履歴の置き換えを案内する。作成日時の制約とExifToolの技術情報はヘルプに表示する。更新後は成功／スキップ行の一時表示をサポートし、手動再スキャンで解除。読み取りエラー／更新時スキップ行では、状態列の情報アイコンから簡潔な理由を確認できる。
- Android：要更新優先を初期表示とし、ファイル名順・撮影日時順に切り替えられる。撮影日時と変更日時はそれぞれ「撮影：」「変更：」の2行に表示し、状態はファイル名と同じ行に置く。相対パスは省略可能な1行表示とし、フォルダ名の独立行を設けない。読み取りエラーの理由は一覧から確認できる。ファイル名から縮小プレビューを表示し、一覧の「関連付けアプリで開く」ボタンまたはプレビューから対応アプリに画像を読み取り専用で渡す。対応アプリがないRAW等は開けない。選択行の表示、全選択／全解除。スキャン・更新の中止と進捗表示。書込権限は本人が承認する。
- 写真を識別するため、**選んだ1枚だけ**縮小画像を表示する。MacはQuick Lookで取得して右欄に、AndroidはOS標準ThumbnailUtilsで取得し、ファイル名を押すとダイアログに表示する。左右スワイプまたは「前へ」「次へ」で一覧順に移動し、閉じると最後の画像の位置に一覧を戻す。取得できない形式は「プレビューできません」とし、関連付けアプリで開く導線を残す。写真・EXIF・mtime・Undo・チェック状態は変えない。**一覧各行へのサムネイル、キャッシュDB、RAW独自現像、拡大、新たな設定画面・複数フォルダ同時操作は追加しない**。

## 更新・Undoの安全条件

- **更新はmtimeだけ**。対象がスキャン時から変化していたら更新せずスキップ。ルート外、シンボリックリンク、ハードリンクなど危険なファイルを拒否する。
- 最新1バッチの更新前mtimeと更新後の確認値を永続保存し、アプリ完全再起動後にもUndo可能。新しい更新で直近履歴を置換する場合は事前に説明。**Macの更新中止は協調停止**：書き込み途中の1件を強制中断せず、検証・書込・記録の安全な境界で残りを停止する。書込開始前に中止した場合は既存Undo履歴を置き換えない。一部更新後に中止した場合は成功分だけUndo対象に残し、未処理件数を表示する。
- Undo前にファイル識別情報・サイズ・更新後mtimeを照合し、競合するファイルは復元しない。Macで書き込み途中にエラーが起きたらバッチを停止し、`pending`／`undoPending`など未確定の履歴を保持し、自動復旧・無条件再試行は行わない。
- Androidは署名違いによるAPK入替時にUndo履歴が失われないよう、アプリデータ削除・アンインストールを自動実行しない。

## 性能・配布・対象外

- Macのスキャンは最初の5枚、以後20枚ずつExifToolで読み取る。更新直前の再確認は画像ごとに行う。更新後は全フォルダを再スキャンする。
- Mac App Store配布やSandboxの再設計は初期版対象外。macOS個人用ビルドは外部ExifToolが使用できる構成でローカル生成する。
- 時差補正、動画、ファイル移動・リネーム、NAS／クラウド／SDカード、CSV、詳細履歴、独自EXIF解析、ライブラリ改造、過剰な診断機能は対象外。画面はDADSの読みやすさ・アクセシビリティ原則を参考にする。

試験方法は[WORK_TEST_RUNBOOK.md](WORK_TEST_RUNBOOK.md)を参照してください。
HIFはMacのスキャン対象候補に含む。専用コピー1件ではMacのExifToolで日時を読めたが、AndroidX ExifInterface 1.4.1は撮影日時を取得できなかったため、Androidでは対象外とする。
